# 문제 해결

0. 가정 명시: 구현 전 가정을 나열. 불확실하면 사용자에게 확인
   - 여러 해석이 가능하면 모두 제시 (3-Options 활용)
   - 더 간단한 방법이 있으면 먼저 제안
   - 이해 안 되면 멈추고 질문

   **안티패턴: 숨겨진 가정**
   ```
   # ❌ "유저 데이터 내보내기" → 전체 유저, JSON/CSV, 파일 위치, 필드 모두 가정하고 구현
   # ✅ 먼저 확인: 범위(전체/필터링)? 포맷(브라우저 다운/API/백그라운드)? 필드(민감정보)? 볼륨?
   ```

   **안티패턴: 여러 해석을 조용히 선택**
   ```
   # ❌ "검색 빠르게 해줘" → 캐시+인덱스+비동기 200줄 추가 (latency인지 throughput인지 확인 없이)
   # ✅ 제안: 1) 응답시간 단축(인덱스) 2) 동시처리 향상(async) 3) 체감속도(점진 로딩) — 어떤 게 필요?
   ```
1. 분석: 파일 구조와 관련 코드를 먼저 읽고 분석
2. 원인: 문제의 근본 원인을 논리적으로 추론
3. 계획: 단계별 해결책 제시
4. 백업: `git tag`로 `vx.x.x` patch 하나 올려서 `checkpoint` 기록
5. TDD: 계획 수립에 맞게 테스트 코드 작성
6. 실행: 개발 시작
7. 검증: `make`를 이용해 테스트 코드 검증
8. 복구: 심각한 오류가 있을 때만 사용자의 동의 후 `checkpoint` 되돌림
